EIC Streaming Data Path

The ePIC detector has no hardware trigger, so background has to be thrown away inside the readout chain, on data that is still flowing. That sets the two hard limits this benchmark scores against: a bandwidth cliff at every stage, and a 0.6 ms time-frame to finish in.

Limits a submission must live inside

  • ≤ 0.6 msend-to-end per time frame (proposal figure, still marked TBD)
  • ~1.4 Tb/sfilter input: ~5,700 hits × 15 features per 2 µs window, float32 (computed in README §1)
  • ~97% LUTreference HLS kernel at sequence length 600 on an Alveo U250
  • 127 KBcompressed HEPTv2 weights, small enough to stay on-chip

Unconfirmed: the AI filter's placement (DAM/EBDC vs. RDO) is the slide's proposal, not a decided design. The 0.6 ms budget is the proposal's working number. The EICrecon timings come from a different study configuration and have not been re-measured on this benchmark's data.
